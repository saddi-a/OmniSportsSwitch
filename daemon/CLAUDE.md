# daemon/ (guide for Claude)

The Python daemon: one asyncio process (`python -m daemon.server`, started by `scripts\start_all.ps1`) that listens on `ws://127.0.0.1:8765`, receives audio and reports from the extension, scores each stream, and sends back "arrange" (move tabs) and "focus_tile" (DAZN multiview) commands. Read `PLAN.md` sections 3, 5 and 6 for the rules these files implement.

## Files

| File | Job |
|---|---|
| `server.py` | The `Server`: message handling, the loops (classify audio, OCR, decide swaps), per-tab/per-tile state, slot limits (tab choice + team rules), expand confirmation. Where everything is wired together. |
| `scoring.py` | `Scorer`: score of each stream from audio signals, events, favourites and status; `decide()` picks swaps (margin, minimum score, warm-up, dwell); `evict_main()` hands MAIN over when its stream may not be there. A multiview tab keeps one `_Tile` record per video (`_Stream.tiles`: event, goal hold, hot episode, cue, leverage, replay, ad, state), `components()` scores each tile with its own sport and the tab as its best tile (keys `tile`, `sport`, `tile_scores` added); audio goes to the tile `audible_of(tab)` names. Pure logic, takes `now`. |
| `game_state.py` | `GameTracker`: live / break / over, commercial placeholders, big-play banners, per sport profile. Pure logic. |
| `score_watch.py` | `ScoreWatcher`: finds the score on a scoreboard from OCR items (team-anchored, geometry), votes over readings, detects a goal. |
| `scoreboard_profiles.py` / `scoreboard_templates.py` | Per-SPORT reader rules (profiles) and per network / league scorebug layouts (templates) used by `find_score_geo`; see `docs/scoreboard-profiles.md`. |
| `sport_detect.py` | Guesses the sport from scoreboard cues, with accumulated evidence. |
| `favourites.py` | Matches favourite teams (`match_multiplier`) and team slot rules (`match_slots`) against text. |
| `team_names.py` + `team_tables/` | Team-name table, one hand-edited text file per sport (`football.txt` = soccer incl. UEFA clubs, `nfl.txt`, `cfb.txt` = FBS; a new sport = a new file): per club the ESPN code and displayName plus broadcast aliases (MAN U, PSG, BAMA, TXAM...). `[ambiguous ...]` lines (REAL, FCB, MSU, OSU, GEORGIA, MUN...) and 2-letter codes (OM, OL, ND, KC...) are CANDIDATE tokens: no club gets them as an alias, every club they may mean accepts them, only as whole word (2-letter ones in upper case). `feed_map.shows_game` needs both teams of the game and one token never stands for both (REAL alone = no lock; MUN is Bayern AND Man United, the opposing team decides, then the score/clock fit; two fitting games stay ambiguous). `x?` = doubtful, unused. The table is added AFTER the hand-written `feed_map.ALIASES` (override layer, never reduced). Tests: `test_team_names.py`, code fixture `fixtures/espn_team_abbrs.json`. |
| `arrange.py` | `plan_swap` (who moves where, honouring allowed slots, three-way rotations) and `plan_fix` (correct tabs in slots they may not use); both take `fixed` (slots that must not move: Window 2 = LEFT while held or frozen; a rotation never uses one, a swap that needs one is refused). `plan_move` puts a tab into a slot (Make Window 2). Pure logic. Window 2 controls: `Scorer.force_window2` / `hold2_left` / `window2_fixed` / `frozen2` / `fixed_tabs` (never a challenger), `Server.fixed_slots`, `_handle_window2_control`, `_log_skipped` (warning at most every 10 s), messages `freeze2`, `force_window2`, `release_hold2`, `get_hold2`, setting `manual_hold2_s`. Tests: `tests/test_window2*.py`. |
| `multiview.py` | `TileFocuser`: which tile of a multiview tab should have the sound / be expanded. A tile may carry the Scorer's `score` (`Scorer.tile_scores`); when every tile has one it replaces event + crowd (the wanted tile), 30 s dwell and 1.5x ratio unchanged; `Server._focus_commands` waits while `pending_expand` runs. |
| `screen_ocr.py` | Screen capture of a video area (mss) and EasyOCR (GPU); also clock finding. |
| `rapid_reader.py` | Second OCR reader (PaddleOCR models via `rapidocr-onnxruntime`, CPU): runs only on a tile with a scorebug but no score or clock, merges its items into EasyOCR's, then the digit slots. Fail-safe. Setting `ocr_assist`. |
| `score_slots.py` | Reads the two score digits slot by slot between the team names (recognition only, confident readings vote). |
| `feed.py` | Outside game data (ESPN's public JSON), MEASURING ONLY (`scoring.feed_mode` 0 = off = nothing starts, 1 = record; needs a restart): parsing into `Snapshot`/`FeedEvent`, `FeedTracker` (what changed), `Poller` (when to ask, back-off), `FeedRecorder` (`logs/feed/<date>.jsonl`), `FeedSession.step` (run in a thread by `Server._feed_loop`). Changes no score or swap. `feed_compare.py` + `scripts/feed_compare.py` measure the lead of the feed over each stream. `feed_map.py` (Stage 1, measuring only): `FeedMapper` ties each (tab, tile) to a feed game by voting over OCR team names + popup teams text, locked only while the OCR score/clock fit the feed's timeline; logs `feed map ...`. `feed_gate.py` (Stage 2 shadow lines + Stage 3a feed goals, referee, rewind; applies nothing itself, the server drains `Fired` x `scoring.feed_event_weight`; also the football end-zone cue lines from `feed.parse_situations`): `FeedGate` compares feed events with the stream clock of mapped tiles, logs `feed would-fire/confirmed/unconfirmed/skipped/ocr-only` (lead `scoring.feed_lead_s`). Plan: `docs/api-plan.md`. |
| `backtest.py` | OFFLINE and read-only (`scripts/backtest.py`): replays `logs/` to measure how far AHEAD of each goal a stream's score was (30/20/10/5 s before), when the swap rule and the build-up tracker would have qualified, per sport. Pure parsing and arithmetic, tested in `tests/test_backtest.py`. It also uses the feed recordings (`logs/feed/*.jsonl`) as ground truth (`parse_feed_events`, `parse_mappings` from the `feed map` lines, `measure_feed`, `summarise_feed`; tests in `tests/test_backtest_feed.py`): per sport feed goals detected or missed by the OCR, the feed's lead over the picture, how far before the picture goal the swap rule / build-up / first cue / the feed were available, OCR-only changes, and base rates of cards etc.; measuring only. |
| `buildup.py` | `BuildUp`: the cues of a stream added together over `scoring.buildup_window_s` (the scorer keeps only the strongest). `Server._check_buildup` logs `buildup would take MAIN` for football and, with `scoring.buildup_live` > 0 (default; 0 = log only) and a sport detected as exactly football (`moves_main`), moves MAIN through `Scorer.take_main` (same guards as a normal swap: `take_main_block`; reason 'build-up: level ...'); no score changes. A football loudness surge >= `buildup_surge_min` also notes a small pseudo-cue (`buildup_surge_note`, once per cooldown, `surge_note_due`) so the log shows when surge plus cues would have sufficed; never set_anticipation. 2026-10-12 more aggressive defaults: `buildup_min` 0.32, own gap `buildup_gap` 0.10 (not `min_gap`), `buildup_surge_min` 0.6, `buildup_window_s` 60, and a crowd >= `buildup_crowd_min` 0.25 on 2 consecutive score readings notes `buildup_crowd_note` 0.10 (`crowd_note_due`); the stream cooldown starts only when the swap really happens (`would_take(start_cooldown=False)` + `mark_fired`), a blocked try may repeat on the next reading and logs 'not moved' at most every 10 s (`blocked_log_due`). Post-goal replay hold (`Scorer.goal_hold_left`, `goal_at` set by `set_event(goal=True)` from score change / goal banner / feed goal): `take_main_block` refuses 'goal on MAIN N s ago' for `goal_hold_s` 40 s after a goal on MAIN, extended to (last replay sign + `goal_hold_extend_s` 10) up to `goal_hold_max_s` 75 s after the goal by `note_replay` (stream.replay, hidden scorebug, replay by clock, spoken 'replay'); a challenger scoring >= `goal_hold_break` 0.8 breaks it; logs 'post-goal replay hold tab T until +N s' / 'post-goal replay over tab T after N s'. The soccer rising-sound cue (`cues.SurgeRiseWatch`, `Server._check_surge_rise`: loudness grown `surge_rise_ratio` over `surge_rise_window_s` with a surge >= `surge_rise_min`, voted on `surge_rise_votes` readings, cooldown; weight `cue_surge_rise` 0.20; build-up kind `surge_rise`, dataset event `surge_rise`) fires before the commentator's words; `Scorer.blowout_goal_bonus` lets a fresh goal in a decided game win MAIN only while all other streams are quiet (`blowout_goal_*`). A spoken football `corner` is also noted at `cue_minor` x `speech_cue_factor` (`cues.tracker_note_weight`; tracker only, no score, no set_anticipation; log 'buildup note corner'). Pure logic. |
| `speech.py` | Local speech to text (faster-whisper) and `CUES`, the phrases heard. `CUE_SPORTS` lists the sports each spoken cue is valid for (red zone/touchdown only American football, corner/card/goal only soccer, review/replay/foul/timeout any); `find_speech_cues(text, sport)` drops the others, an unknown sport keeps all. On a soccer stream the scoring cues (penalty, penalty awarded, foul, offside, chance, post, post area, goal, free kick, card, corner; `FILTERED_CUES`) also skip negations and recaps per match: `is_recap_or_negation` tests the last 4 words / 30 characters of the same clause BEFORE the match against `NEGATION_OR_RECAP` ('pas de', 'sans', 'avait', 'ce qui amène', 'sur ce', 'no', 'not', 'was', 'had'...) and the text just after against `RECAP_AFTER` ('justement', 'déjà', 'obtenu'); review/replay/var and American football are never filtered. Banner cues have the same table in `game_state.BANNER_CUE_SPORTS`. `post` = the ball hits the woodwork; `post area` (soccer only) = positional 'premier/second poteau', 'near/far post', a MEDIUM spoken cue (`cues.SPEECH_SCORING` 'mid' = `cue_review_mid` x `speech_cue_factor`). `chance` counts 'c'est capté' / 'repoussé' only after a shot word (frappe, tir, reprise, volée) in the same clause (<= 40 chars); 'capté en deux temps' and keeper phrases always count. |
| `audio_classifier.py` | PANNs Cnn14 on the GPU, 32 kHz audio, 527 AudioSet classes. Models live in `models/panns/`. |
| `settings.py` | Loads `settings.toml` (the defaults) plus `settings.local.json` (what the user changed in the popup) into the config objects, and lets the popup read, change and reset them live (`describe`, `apply_changes`, `reset_all`). Also reads the per-sport override tables (`[scoring.<sport>]`, `[weights.<sport>]`, file only) into `Config.sport_scoring` / `sport_weights` (`_read_sport_overrides`: unknown sport/key, a non-number or a key outside `OVERRIDABLE_SCORING` is ignored with a warning); `reset_all` leaves them alone. |
| `logsetup.py` | Permanent logs in `logs/` with a gzip ARCHIVE: `ArchivingRotatingFileHandler` compresses each file that rotates out into `logs/archive/<YYYY-MM-DD>/<name>.<stamp>.gz` in a worker thread (nothing is lost); `archive_rotated` completes it at start, `prune_archive` deletes by `scoring.log_archive_days` (90) and `log_archive_max_mb` (50000), both run hourly by `Server._maintenance_loop` in a thread. Live rotation sizes are module constants (`DAEMON_LOG_BYTES` 20 MB x 10, `EVENTS_LOG_BYTES` 5 MB x 20, `BOXES_LOG_BYTES` 20 MB x 5). Errors are logged once, never raised. |
| `recorder.py` | `DatasetRecorder` + `snapshot_rows`: the learning data in `logs/dataset/<date>.jsonl` (one row per stream every 2 s, called at the end of `Server._log_scores`) and `<date>.events.jsonl` (`Server._rec_event` / `_rec_swap`: swaps, score changes, cues, speech text, game states, build-up decisions). Bounded queue + writer thread, drops (counted) rather than blocks, `scoring.dataset_mode` 0 = off (read live); not archived, never pruned; `Server(recorder=None)` in tests so they write nothing. Format: `docs/dataset-format.md` (a field is only added, never renamed). `BuildUp.note(..., kind)` labels each cue for the rows. |
| `swap_review.py` | OFFLINE swap review (`scripts/review_swaps.py`, pure): the day's swaps from `logs/dataset/<date>.events.jsonl` (else `events.log`), user swaps excluded, context -30..+60 s of both tabs, games from `feed map` lines, the user's remarks from `logs/feedback/<date>.md`, flags (flip-flop within 30 s, quiet tie, goal/penalty/red card nearby). Marks (good/regret/late/missed-chance/other) append to `logs/review/<date>.jsonl`, last wins; `--markdown` writes `logs/review/<date>.md`. Writes nothing else. |
| `dataset_builder.py` | OFFLINE and read-only on `logs/` (`scripts/build_dataset.py`, writes only `logs/dataset_built/`): recorder rows + events + feed recordings (+ the user's marks of `swap_review`) -> labelled rows (`y_goal_30`, `y_t12_60`, `y_t1_60`, per-game picture lag by on-screen clock / OCR score change, unaligned rows left unlabelled), per-swap REGRET verdicts and tier-1/2 MISS / lead per event, per sport. Method and verdict rules: `docs/dataset-format.md` "Dataset builder". Tests: `tests/test_dataset_builder.py`. |
| `espn_history.py` | OFFLINE only (never called by the daemon): ESPN's finished-game data for soccer. Polite fetcher with an on-disk cache `logs/feed/history/<league>/<event>/` (gitignored; summary + core plays pages; sequential, >= 2 s apart, the daemon's User-Agent, `fetch`/`sleep` injectable, a complete cached game is never refetched, a game whose summary is not post/FULL_TIME is skipped) and the parsing of the summary `commentary` list and the core plays into normalised, tiered events (tier table, position rule for shots in the box, penalty-awarded-by-text, VAR texts: module docstring and `docs/dataset-format.md`). `dataset_builder.build(commentary=...)` adds the tier-1/2 ones next to the feed events (`scripts/build_dataset.py --fetch-history`). Tests: `tests/test_espn_history.py`, `tests/test_dataset_commentary.py` (synthetic, no network). |
| `tests/` | pytest suite; `tests/fixtures/*.json` are real OCR readings (items with boxes) from screenshots. |

## Rules for changes

- Keep decision logic **pure** (callers pass `now`, no sockets, no sleeps) so it can be tested; only `server.py` touches time, sockets and threads.
- Every tunable number goes in `Config`/`Weights` (or a sport profile) **and** `settings.toml`; `tests/test_settings.py` fails if they drift apart. To make it editable in the popup, also add it to `LAYOUT` in `settings.py` (id, label, help text); the popup draws itself from that, so `extension/` needs no change. Settings objects are changed in place while running, so read `config.x` when you use it; never copy a value at startup. A value that is read where the stream's sport is known is read through `config.for_sport(sport)` (`Scorer.cfg_for(tab_id)`; per-sport overrides from `[scoring.football]` / `[weights.football]` in `settings.toml`, shared value otherwise); to make a new tunable overridable per sport, read it that way at every site that uses it and add it to `OVERRIDABLE_SCORING` in `scoring.py` (weights are all overridable).
- A tile's sport comes from `Server.tile_sport(tab, tile)` only; a tab's sport for the Scorer, speech and build-up is `audible_sport(tab)` (`_tab_sport`): the popup choice, else the audible tile's sport (unknown audible tile in a multiview = football). Do not read `sports`/`sport_seen` directly. When the sound moves tile, `_note_audible` drops the old audio.
- A multiview tab is scored per TILE (Stage 2, `docs/per-tile-sport.md`): `Scorer._Stream.tiles[index]` (`_Tile`) holds each video's picture signals and the setters take `tile=` (None = the tab's only video, which uses the stream itself: keep that path identical, `tests/test_per_tile_scoring.py` has a golden sequence). `Server._tkey(tab, index)` gives the argument (None unless the tab shows 2+ videos), `Server._bkey(tab, tile)` the key of `BuildUp` / `SpeechMemory` (tab id, or `(tab, tile)`), `Scorer.tile_cfg(tab, tile)` the settings of the tile's sport, `Server.scoring_sport(tab, tile)` its sport (unknown tile of a multiview = football). The audio (speech, crowd, loudness, music) belongs to the audible tile only: `Server._audible_target`, `Server._hears`. Anything new that is per video must live in the tile record and be swapped in `_expand_swap`.
- Per-tile state is keyed `(tab id, video index)`; per-tab state by tab id. When a DAZN expand swaps streams between slots, the per-tile records must swap too (`_expand_swap`, which must list every per-tile store), only once the expand is confirmed by where the sound went.
- OCR is noisy. A single reading must never trigger an event: use votes, memory windows and confirmations. When fixing a misread, add the real OCR items as a fixture and a test.
- Slot limits: `allowed` is what the user ticked on the tab; `limits` = allowed plus team rules (by teams field, or OCR text remembered 10 minutes). Use `limits` for planning.
- Run `.venv\Scripts\python.exe -m pytest daemon -q` before every commit. The one expected failure is the UCF layout (`test_ucf_layout_with_a_logo_read_as_a_digit`).
